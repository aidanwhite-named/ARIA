# 올바른 청구항 재실행의 전달 비용 점검

대상 실행: `2f3b7811-bce9-4fc5-9145-5683b022a2c8`.
비교 실행: `c1087b81-51d8-464c-a3d6-5071d917c360`.
청구항·분석 프롬프트·순서별 PDF 해시 및 provider/model이 일치한다.
두 실행 모두 5라운드, 반환 56,000자, 페이지 80쪽, 근거 100,000자 설정이다.

| 항목 | 이전 | 이번 |
|---|---:|---:|
| 미처리 요청 | 29 | 18 |
| 열람한 고유 페이지 | 8 | 7 |
| 기록상 검색 total_tokens 합계 | 168,993 | 179,784 |
| 기록상 최종 생성 total_tokens | 51,005 | 48,546 |
| 위 두 값 합계 | 219,998 | 228,330 |
| 전체 소요 시간(ms) | 119,969 | 113,419 |

모델 응답이 달라지는 단일 실행 비교이며 변경만의 인과 효과를 입증하지 않는다.
thinking_tokens는 total_tokens와 별도로 더하지 않았다. 결제 금액 추정은 아니다.

## 이번 제한의 실제 위치

- 고정 후보 목록 35개, 후보 연결 177건 중 124건 전달, 53건 미전달.
- 미처리 검색 18건 중 15건이 첫 라운드에서 시작했다. 페이지 재열람은 0회다.
- 4·5라운드의 모델 응답은 finalize_evidence였지만 이월이 남아 거절됐고,
  마지막에는 회차 제한 상태로 저장된 마무리 응답을 채택했다.
- 최대 라운드 입력은 103,745 bytes다. 현재 코드의 agy 전송 상한 180,000
  bytes에 도달한 것이 아니라 반환 문자 예산 및 회차 제한이 걸린 것이다.
- 최종 패키지에 ATT-02 11쪽, ATT-03 11·9쪽 제외와 ATT-04 6쪽 부분 수록이
  남았다. 후자는 5,052자 중 2,330자 수록이다. 패키지는 94,099자다.

## 아직 남은 비용

1. 원문과 필드 내용을 바꾸지 않고 JSON 들여쓰기·구분 공백만 제거했을 때
   5회 입력에서 총 69,128자가 줄어든다. 이는 문자 수이며 토큰 절감률이 아니다.
   현재 반환 예산 계산도 indent=2 직렬화에 기반하므로 포맷 비용이 후보와 경쟁한다.
2. 2~5회차 검색 결과에서 본문이 실린 후보 77행 중 13행은 이전 회차에 본문을
   전달한 동일 (문헌, chunk_id)다. 이들 본문은 합계 7,888자다. 별도 페이지
   본문이나 앞뒤 문맥과의 부분 중첩은 이 수치에 포함하지 않았다.
   매 회차가 독립 모델 호출이므로 이를 무조건 생략하면 근거를 못 보게 된다.
   여러 구성에서 같은 원문을 재사용하는 계획과 현재 호출의 근거 묶음이 필요하다.
3. 첫 라운드 반환 사용량은 실행기의 json_size 합계로 36,398자이며,
   56,000자 중 19,602자가 남았지만 25개 요청이 이월됐다. 예약 몫 및 action별
   배분에 못 들어간 후보를 잔여 공간에 다시 담는 단계가 없다.
   이후 라운드 2~4의 사용량은 55,999 / 55,963 / 55,950자다.

첫 검색 후보의 120행은 semantic만으로 찾아졌다. 이는 120개의 고유 문헌
구간이거나 모두 유용/불필요하다는 뜻은 아니다. 관련성 검증 없이 의미 검색을
끄거나 후보를 삭제하는 것으로 0건을 만들면 검색 범위가 달라진다.

다음 우선순위는 JSON 전송 형식 압축과 남은 반환 공간 재배정이다. 의미 검색,
원문, 회차 상한을 유지한 재생 비교 후 공유 근거 전송을 추가 검토한다.
이번 점검에서는 실행 코드를 수정하거나 AI 보고서를 재생성하지 않았다.

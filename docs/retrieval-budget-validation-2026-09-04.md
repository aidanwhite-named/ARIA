# 검색 이월 및 실행별 근거 예산 검증 — 2026-09-04

파싱 오류를 결과 화면에 표시하고, 검색 요청의 대기 이력과 중복 이월을 수정했다.
근거 패키지의 문자 상한과 실행별 바이트 상한을 분리했다.

## 확인한 원인과 변경

- 기존 실행의 페이지 읽기는 10/80쪽이었다. 페이지 한도는 이번 병목이 아니었다.
- 이월 이벤트 540건 중 401건은 `attempts=0`이었고 최댓값은 5였다. 구성·문헌·action으로 묶은 32회는 동일 요청 하나의 대기 횟수가 아니다.
- `_search`와 `_read`가 일부 결과를 재이월할 때 `first_round`와 `attempts`를 초기화했다. 이제 부모 요청의 대기 이력을 이어받고 중복 요청을 합칠 때 더 오래 기다린 이력을 유지한다. 대기 가중치의 5회 상한도 제거했다.
- 라운드에 최소 응답 형식도 넣을 수 없을 때 원래 요청과 문헌별/페이지별 후속 요청을 함께 이월했다. 이제 원래 요청 하나만 이월하고, 반환하지 않은 결과는 열람 상태에 반영하지 않는다.
- `analysis_manifest_error`는 보고서 앞의 오류 안내에 표시한다. 기존 실패 기록에도 적용된다. 본문은 유지하며 미대응 구성 검색이 비활성인 이유를 설명한다.
- preflight와 runner가 같은 조립본으로 청구항·지시문·첨부 메타데이터·경계 표시를 센다. 실제 Provider 측정 함수와 모델 토큰 추정 한도를 반영해 `max_evidence_bytes`를 결정하고 검색 실행에 전달한다. `fit()`은 문자·바이트 상한을 각각 강제한다.
- 문자 기본값은 기존에 선택한 54,000자를 유지했다. 이는 고정된 안전 최대가 아니다. 100,000자와 200,000자 요청도 실행별 바이트 상한 안에서 처리하는 경로를 검증한다.
- 결과 화면에도 바이트 상한을 표시하고, 문자 예산을 올리면 항상 축약이 없어진다는 안내를 수정했다.

## 같은 자료로 실행한 결과

원본 작업: `4b968a73-c1dc-4eac-bb1d-1e09ed2619c0`

최종 검증 작업: `6d0bddea-cc03-4330-92ce-47d448563c00`

PDF 4건, 청구항 463자, `agy / gemini-3.7-flash-low`, 의미 검색 사용.
최대 10라운드, 페이지 읽기 80쪽, 라운드 반환 24,000자는 유지했다.
원본의 문자 예산은 40,000자였고 이번 실행은 54,000자다.

| 관측 항목 | 원본 | 최종 검증 |
|---|---:|---:|
| 앱 실행 상태 | 성공, 구성 블록 파싱 실패 | 성공, 파싱 오류 없음 |
| 마지막 미처리 요청 | 73 | 29 |
| C·D 미처리 요청 | 45 | 16 |
| 반복을 포함한 이월 이벤트 | 540 | 260 |
| 실제 반환된 페이지 | 10 | 12 |
| C의 최종 근거 | 0 | 2 |
| D의 최종 근거 | 0 | 2 |
| 서지 확인용 발췌 | 0 | 4 |

최종 입력은 80,586 bytes로 agy 한도 180,000 bytes 안에 들어갔다.
최종 보고서는 C를 부분 대응 60%, D를 실질 대응 90%로 출력했다.
C에서 다른 문헌의 보완 개시, 결합 동기, 결합 후 잔존 차이를 검토했다.
구성별 대응 패널이 나타났고 미대응 구성 검색에서 C 한 건을 선택할 수 있음을 실제 브라우저에서 확인했다. 웹 검색 자체는 실행하지 않았다.

이 비교는 같은 자료를 사용한 실제 실행 관측이다. 모델의 검색 요청과 판단은 실행마다 달라지므로 수치 차이를 코드 변경만의 효과로 단정하지 않는다.

## 남아 있는 제한

- 미처리 요청 29건이 남았다. C 10건, D 6건을 포함하며 전 문헌 검토 완료를 뜻하지 않는다.
- 근거 구간과 서지 발췌는 유지했지만 페이지 전문·주변 문맥 확장 14건은 문자 예산 때문에 빠졌다.
- 서지 발췌를 복구해도 최종 보고서의 문헌번호 확인 불가 2건은 남았다. 번호 식별은 별도 확인이 필요하다.
- 중간 검증 작업 `a196bad0-7e09-47b6-a0a2-2c56e9da3eed`는 agy가 SUCCESS 결과를 보낸 후 프로세스가 종료되지 않았다. 스트림 결과를 별도로 보관했고, 최종 검증 작업의 정상 완료 후 중간 작업을 취소했다. 완료된 실행으로 집계하지 않는다.
- 원래 앱(8765)을 종료하는 재시작 명령은 자동 승인 검토에서 차단됐다. 수정본은 동일 데이터 저장소를 사용하는 로컬 포트 8767에서 검증했으며, 원래 앱에 새 백엔드를 반영하려면 앱 재시작이 필요하다.

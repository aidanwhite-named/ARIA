# 검색 파이프라인 토큰 효율 개선 및 동일 자료 검증 — 2026-09-04

## 결과 요약

요청 1–5를 구현하고 기존 PDF 3건·청구항·분석 프롬프트·agy 모델을 유지한 채
한 번 재실행했다. 검색 토큰은 37.41%, 최종 보고서까지 합친 기록상 토큰은
27.85% 줄었다. 미처리 요청은 28건에서 12건으로 줄었으나 전 문헌 검토 완료는 아니다.

요청 0의 Claude 비교 호출은 실제 실행했지만 CLI 미로그인으로 실패했다.
도구 스키마의 정확한 토큰 기여분과 Claude의 고정비는 확정하지 않았다.

- 원본 첫 라운드와 동일한 시스템 프롬프트·사용자 메시지 5,938자를 사용했다.

  빈 MCP 설정, 사용자/프로젝트 설정 차단을 적용했다. ARIA 데이터 폴더 아래
  별도 작업 디렉터리에서 호출해 프로젝트 지시문이 섞이지 않도록 했다.
- Claude CLI 2.1.156의 init에서 `tools: []`, `mcp_servers: []`를 확인했다.
- 결과는 exit code 1, `Not logged in · Please run /login`이다. 실패 응답의
  입력 토큰 0은 측정값이 아니므로 비교값과 절편 잔차를 `null`로 저장했다.
- 원본 agy `stdout.log`의 init에는 도구 57개가 광고된다. 주어진 분석의
  51개와 개수는 다르지만, 도구가 비활성화되지 않는다는 관측은 일치한다.
- 제공된 회귀식 `15,415 + 0.311 × input_chars`와 절편의 검색 총량 대비
  약 56% 비중을 작업 가설로 사용했다. 기존 10라운드 회귀를 다시 수행하지 않았다.
- 도구 이름 광고만으로 전체 스키마의 직렬화 크기나 15,415토큰 전부의 원인을
  확정할 수 없다. agy 기본 지시문과 기타 내부 컨텍스트도 구분되지 않았다.
  Claude 로그인 후 비교가 가능해져도, 서로 다른 모델의 단일 표본은 토크나이저와
  시스템 프롬프트 차이가 있으므로 독립적인 회귀 절편이나 도구 스키마 제거 실험이 아니다.

비교 스크립트는 `data/validation/retrieval-efficiency/probe.py`, 실패 원본 응답은
`claude-probe.stdout.jsonl`, 실패 요약은 `claude-probe.json`에 있다.

## 1–5. 구현 내용

1. 검색 기본값을 5라운드, 라운드 반환 56,000자로 변경했다. 라운드 입력은
   문자열 UTF-8 합이 아니라 Provider의 실제 직렬화 측정 함수로 검사한다.
   래퍼·이스케이프를 포함한 `input_bytes`도 라운드 감사 기록에 남긴다.
2. 모델에게 보내는 hit는 `alias`, `chunk_id`, `pdf_page`, `section`,
   `extraction_status`, `text`만 유지했다. 점수·채널·UUID·파일명·추출 방법·
   페이지 내 순서·채널별 순위는 `search_candidates` 감사 이벤트와 내부 후보
   상태에 보존했다. hit 발췌는 최대 900자이며 전문이 아니라는 계약을 명시했다.
3. 구성 선언 시 label→ID 별칭표를 만들고 새 action, 기존 이월 action,
   마무리 action의 구성 식별자를 정규화한다. 이름과 정식 ID로 중복된 이월
   요청은 합치되 가장 오래된 대기 시작과 최대 대기 횟수를 유지한다.
   중복 label이나 다른 정식 ID와 충돌한 label은 임의로 연결하지 않는다.
4. 후보가 0건인 구성별 첫 검색에 반환 예산 30%를 먼저 나누어 배정한다.
   해당 검색만 있는 라운드는 전체 예산을 쓸 수 있다. 0-hit 검색은 후보
   확보를 뜻하는 `searched`에 추가하지 않고 `search_attempts`에 별도 기록한다.
   따라서 +500 첫 후보 우선권은 유지하면서, 0건 검색·누락·실패를 감사와
   검토 범위 판정에서 잃지 않는다.
5. 근거 문자 기본값을 100,000자로 변경했다. 실행별 바이트 상한은 별도로
   유지한다. 페이지별 몫을 넘는 확장 페이지는 앞부분만 수록하고 포함·누락
   글자 수와 범위를 기록한다. 부분 수록은 전문 확인 페이지에서 제외하며,
   패키지·manifest·화면에 `page_truncations`로 표시한다. 핵심 근거 청크는
   기존처럼 원문으로 유지한다. 전체 패키지 상한 때문에 페이지 전체를 빼는
   경우는 여전히 `page_reductions`에 기록한다.

사용자가 저장한 명시적 설정값은 덮어쓰지 않았다. 이번 자료에는 해당 기본값을
덮어쓰는 설정이 없어 5라운드·100,000자 기본값이 실제 실행에 적용됐다.

### 구성별 hit 수

동일한 manifest 집계 기준이다. hit는 구성별 누적 반환 건수로 중복 후보를 포함한다.
고유 후보 수는 별도 열로 구분한다. 이는 근거의 적합성 점수나 최종 인용 건수가 아니다.

| 구성 | 원본 hit | 개선 후 hit | 원본 고유 후보 | 개선 후 고유 후보 |
|---|---:|---:|---:|---:|
| 전제부 R001 | 0 | 17 | 0 | 17 |
| A R002 | 0 | 37 | 0 | 33 |
| B R003 | 16 | 31 | 16 | 31 |
| C R004 | 35 | 47 | 29 | 41 |
| D R005 | 33 | 28 | 33 | 28 |

첫 라운드 식별자 연결 문제가 해결되어 개선 후 미처리 요청의 구성 식별자는
모두 R001–R005였다. 모델에게 실제 전달된 hit 필드는 요청한 6개뿐임을 재확인했다.

## 남은 제한과 운영 반영

- Claude 비교 측정은 로그인 후 재시도가 필요하다. 0번을 완료했다고 보고하지 않는다.
- 미처리 요청 12건, 페이지 전체 제외 3건, 페이지 부분 수록 1건이 남았다.
- 검색 후보가 늘었다고 최종 판단의 정확성이 검증된 것은 아니다. 논문의 추출 경고나
  도표·수식의 시각적 검토 여부도 이번 효율 변경으로 해결되지 않는다.
- 한 번씩의 확률적 모델 실행 비교다. 검색어·요청·선택 근거가 달라졌으므로
  토큰 감소나 페이지 증가를 코드 변경만의 효과로 단정하지 않는다.
- 기록상 토큰을 합산했다. 실제 결제 금액이나 계정 quota 차감량 측정은 아니다.
- 기존 변경사항은 보존했으며, 기존 서버는 종료하지 않았다. 수정 코드는 별도
  로컬 포트 8768에서 검증했다. 일반 앱에 반영하려면 백엔드 재시작이 필요하다.
  검증 완료 후 이번에 시작한 8768 서버만 종료했으며 기존 서버들은 유지했다.
